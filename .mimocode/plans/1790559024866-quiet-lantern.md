# 课表编辑模式（本轮：进入编辑态 + 加课 + 保存/取消）

## 需求与已定选择

点顶栏左上角编辑按钮进入编辑态：顶栏折叠收起、日期层消失、日期行与周数胶囊消失、底部导航栏消失，
改为三个按钮（保存 / 切换课表 / 取消）；空格子显示"添加卡片"（上起止时间、中间加号），
点它弹出添加课程弹窗（课程名 / 教师 / 上课地点 / 上课周数 / 卡片颜色）。

已确认：**上课周数用方格点选**；**本轮只做加课**（点已有卡片无反应）；**切换课表按钮置空**。

另外定下的（详见「行为约定」）：编辑态固定当前周、置灰卡片可点开添加、保存后退出编辑态、
取消与返回键都丢弃草稿、颜色取设计稿近似值。

## 行为约定

1. 编辑态**固定在进入时那一周**：设计稿里编辑态没有周次指示，翻周无从判断，故 `userScrollEnabled = false`
   并停用折叠（顶栏换成了固定编辑栏）。加课的周次由弹窗里的周数决定，不靠"翻到那周"。
2. 本周不上的**置灰卡片视为该格空着**：卡片保留可见（能看出另一单双周占着），点它同样打开添加弹窗——
   否则那一格永远加不了课。
3. 编辑态**一律显示全部课程**（非本周的照旧置灰），不受「显示本周不上的课」开关影响：开关关掉时
   若把它们藏起来，用户看不见"占着这一格但本周不上"的课，加课撞上冲突却找不到原因。
   普通态仍然照旧听这个开关。
3. **保存成功才退出编辑态**；**取消 / 返回键**丢弃草稿（零写盘，数据层没有事务/回滚接口）。
4. 进入 / 退出编辑态不加过渡动画（与设置页覆盖层一致，瞬时切换）。
5. 颜色：保存绿 `#22B14C`、取消红 `#F5222D`（设计稿近似），切换课表用 `Primary`；三个图标
   （`ic_calendar_checkmark` / `ic_calendar_cancel` / `ic_add`）仓库里本来就有且未被使用。

## 实现

### 草稿只在 UI 层，保存才落盘

- 新 `ScheduleEditSession`：进入编辑时快照 `schedule.courses`，添加只改草稿（`courses` 是 Compose state，
  网格直接渲染它）；`addedCourses()` = 草稿里 id 不在快照里的课。
- **保存**：先 `ScheduleValidator.validateCourses(schedule.copy(courses = 草稿))` 整份预检（挡掉部分落盘），
  再对新增的课逐条 `repository.upsertCourse(scheduleId, course)`（每条自带 uuid，一次一条原子写），
  全成功才退出；失败 Toast 并留在原地。
- **取消**：会话换成占位，草稿消失，零写盘。
- 弹窗内冲突校验针对**草稿 + 新课**，所以"刚加还没保存的课"造成的冲突能立刻报出来。

### 实现中撞到并解决的三处

1. **`rememberSaveable` 不接受可空值**（`fun <T : Any> rememberSaveable`），所以会话不能是 `ScheduleEditSession?`。
   改法：会话带 `active` 标记，非编辑态用 `ScheduleEditSession.Inactive` 占位，Saver 把 `active` 一起存 →
   旋转 / 进程重建后"在不在编辑态"与草稿都能对上（`listSaver` 的返回类型是 `Saver<T, Any>`，声明照它写）。
2. **两套 `CourseColor`**：`data.model.CourseColor`（落库）与 `ui.schedule.CourseColor`（自带 `barColor` 配色）。
   弹窗的色块用渲染层枚举（同包，配色在它身上），构造 `CourseEntry` 时按 name 桥接
   （`DataCourseColor.valueOf(color.name)`，与 `ScheduleAdapters` 同一套做法）。
3. **`WeekPage` 不能记忆内容**：原先 `remember(page, contentForWeek) { contentForWeek(page + 1) }` 的 key 没变，
   草稿更新后不会重算 → 刚加的课刷不出来。改为直接调用 provider（provider 内部会读草稿 state，
   从而把页面订阅进去；重算成本只是几十个对象）。

### 顶栏高度：两种模式各存一份

网格 `contentPadding.top` 依赖顶栏实测高度。编辑栏与头部高度差得多（约 112 vs 168dp），
若共用一个 state，切换模式的首帧内容会跳一下 → 改成 `headerHeight` / `editBarHeight` 两个 state，
各自被对应顶栏的 `onGloballyPositioned` 更新，切换模式立刻拿到上一轮的实测值。

## 上机反馈修正（一）：添加课程改用页内面板

最初怀疑是 `AlertDialog` 的独立窗口接不住输入法，于是改成页内覆盖面板（`AddCoursePanel`）。
**事后证明这个判断是错的**（真正原因见下一条），但改动仍值得保留：`imePadding()` 让面板在
键盘弹起时整体上移（Android 15+ 不再响应 `adjustResize`，弹窗会被键盘盖住），打开即聚焦、表单也更好用。

## 上机反馈修正（二）：键盘唤不起来的真正原因（logcat 定位）

现场日志（`ImeTracker` / `InsetsController`，pid 15199 = 应用进程）：

- `09:37:14.871 onRequestShow … SHOW_SOFT_INPUT_BY_INSETS_API` → `09:37:15.358 onShown`：**键盘确实弹出过**；
- `09:37:18.399` 与 `09:37:24.159` 各有一次 `InsetsController: hide(ime())` +
  `onRequestHide … HIDE_SOFT_INPUT_BY_INSETS_API fromUser false`：是**应用侧程序化收起**，不是用户操作；
- 之后 35 秒内**没有任何 show 请求**，而 09:37:59 的截图显示面板开着、输入框仍是聚焦态（蓝框）。

结论：Compose 的输入框**只在"获得焦点"时拉起键盘**；已聚焦时再点它不会有任何反应，
所以键盘一旦被收起（返回键收键盘 / 系统收起 / 误触遮罩）就再也唤不回来。能粘贴是因为剪贴板
不走键盘通道。修法：

1. 每个输入框监听点按（`interactionSource` 的 `PressInteraction.Release`）主动补一次 `show()`；
2. 返回键改成"键盘在就先收键盘，否则才关面板"。

**另一条线索（次要）**：日志里还有 `libbinder … IInputMethodManager … took 5012ms` 与
`freezeUid SUCCESS: uid=10098 pkg=com.tencent.wetype reason=screen_off`——MIUI 省电策略会冻结
微信输入法进程，输入法调用因此偶发卡住。若新版仍偶发不弹键盘，可把微信输入法的省电策略改为
"无限制"，或临时切到搜狗输入法小米版对照。

## 验证

1. `:app:compileDebugKotlin`、`:app:testDebugUnitTest` 均通过（含新增 WeekSelectionTest）；无新增编译警告。
2. 打包就地安装到设备。
3. 上机清单：
   - 进入编辑态：编辑栏取代顶栏（图标行/日期行/周数胶囊消失）、日期带消失、底部导航栏消失、
     星期行还在且与网格列对齐；网格仍可上下滚动。
   - 空位显示添加卡片（起止时间与课程卡片左对齐、加号居中）；点加号 → 弹窗格子信息正确。
   - 填名/教师/地点、点选周数（含全选/单周/双周快捷）、选色 → 确定 → 卡片立刻出现在网格（未保存）；连加两门。
   - 保存 → 退出编辑态；切 tab 再回来 / 冷启动后仍在（已真正落盘）。
   - 再加一门后取消（或按返回键）→ 编辑态退出且该课未落盘。
   - 冲突：同一格、周数有交集再加一门 → 弹窗内报「与「XXX」时间冲突」。
   - 旋转屏幕：未保存的添加仍在（`active` + 草稿一起存）。
   - 空草稿点保存 → 直接退出，不写盘。
   - 回归：普通态左右翻周、头部折叠、Haze 模糊、tab 平移、周数弹窗均不受影响。
