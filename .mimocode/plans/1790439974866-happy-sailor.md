# 修复：日期带在顶栏模糊中"复活"

## 现象

课表内容上划时日期带（9 10 11 12 13）渐隐消失；继续滚动后，日期数字又从**顶栏模糊**里显现出来（直接视线看不到，只有被 Haze 模糊捕捉到）。

## 根因（已从 Compose Foundation 源码逐行确认）

日期带的渐隐公式**缺少 `firstVisibleItemIndex == 0` 守卫**，而 LazyList 的
`firstVisibleItemScrollOffset` 在物品完全滚入顶部 `contentPadding` 后会被**重置归零**。

时间线（设总滚动量 s，顶栏高度 P = `contentPadding.top` ≈ 160dp，带高 44dp）：

1. `s ∈ [0, 44)`：`firstVisibleItemIndex == 0`，`offset == s`。
   渐隐 `fadeProgress = offset × 3 / 44` 在 `s ≈ 14.7dp` 时到 1 → alpha=0，正常消失。
2. **`s = 44dp`**：LazyListMeasure 的 "ignore items fully located in before content padding"
   逻辑（`LazyListMeasure.kt` L295-311：`size <= currentFirstItemScrollOffset` 时跳过该 item）
   使 `firstVisibleItemIndex` 0 → 1、**`offset` 从 44 归零**。
   此刻带恰好整体位于 `[0, P]` = 完全藏在顶栏背后（直接看不到）。
3. `s ∈ [44, 58.7)`：`offset = s - 44` 从 0 重新爬升 → **alpha 从 1 再次渐隐一次**。
   带在顶栏后变为不透明 → 直接视图被顶栏挡住，但 `hazeSource` 录制的内容里带是可见的
   → 顶栏 `hazeEffect` 模糊把日期数字"捕捉"出来，随后约 15dp 滚动内再淡出。
4. 再往深滚，每个后续 item 边界（每 150dp）offset 都会重置——但那时带已滚出屏幕顶部，
   无视觉影响。**唯一出问题的就是 44dp 这一次翻转。**

对照：`ScheduleScreen.kt` 的 `blurProgress`（L65-73）**已有** `if (index == 0) … else 1f`
守卫，所以模糊强度本身没有跳变——只有日期带渐隐漏了同样的守卫。

涉及文件：

- `app/src/main/java/com/fangyi/classpp/ui/schedule/CourseGrid.kt` — `DateBand` 的
  `.graphicsLayer { … }`（L113-118），唯一缺守卫处。
- `app/src/main/java/com/fangyi/classpp/ui/schedule/ScheduleScreen.kt` — `blurProgress`
  （L65-73），已有守卫，作为参照，不改。

## 修改方案（最小改动）

仅改 `CourseGrid.kt` 中 `DateBand` 的 graphicsLayer 块，镜像 `blurProgress` 的守卫：

```kotlin
.graphicsLayer {
    // LazyList 在带完全滚入顶部 contentPadding（藏进顶栏背后）后会把
    // firstVisibleItem 切到下一项、offset 归零重计；不加 index 守卫会让
    // alpha 在顶栏后跳回 1，被 Haze 模糊重新捕捉到。
    // 与 ScheduleScreen.blurProgress 的守卫保持一致：
    // index==0 时随 offset 爬升，否则视为带已滚过 → 恒为全隐。
    val fadeProgress = if (listState.firstVisibleItemIndex == 0) {
        (listState.firstVisibleItemScrollOffset * DateBandFadeSpeed / bandHeightPx)
            .coerceIn(0f, 1f)
    } else {
        1f
    }
    alpha = 1f - fadeProgress
}
```

行为核对（守卫后连续无跳变）：

- 上滑：`s∈[0,14.7)` 渐隐 → 14.7 后 alpha=0 → 44 处 index 翻转但守卫给 1f → alpha 保持 0 ✓
- 回滑：index 1→0 瞬间 offset=44 → fadeProgress=1 → alpha=0，与翻转前连续 ✓；
  继续下滑 `s<14.7` 对称淡回 ✓
- 深滚/回顶：index≥1 恒 alpha=0，不再有二次"复活" ✓
- 性能：仍在 draw 阶段读 `MutableIntState`，不引发重组（与原实现一致） ✓

不改动：`DateBandFadeSpeed = 3.0f`（渐隐快于模糊爬升是既定设计）、`blurProgress`、
Haze 配置。不做 fade/blur 统一重构（两者速率不同，且共享会引入每帧重组）。

## 验证

1. 构建：`.\gradlew.bat :app:assembleDebug` 编译通过（实现阶段执行）。
2. 真机/模拟器手动滚动：
   - 展开态静止：日期带完整显示，无模糊（回归）；
   - 上划折叠 → 日期带渐隐：与修改前一致；
   - **渐隐完成后继续上划过 44dp 及更远**：顶栏模糊中**不再出现**日期数字（本 bug 验收点）；
   - 深滚若干屏再回滑：带对称淡回，顶栏无闪烁；
   - 回到顶部：布局/图标/周数菜单完全恢复（回归）。
3. `@Preview`（ScheduleScreen / CourseGrid / ScheduleHeader）正常渲染。
