# 底部导航切 tab · 内容平移切换

## 需求与已定方案

点按底部导航栏 → 三页内容横向平移切换（旧页滑出、新页滑入），导航栏与设置页覆盖层都不动。

用户已选定：

1. **连续平移**：三页像一条连续带子一起平移，跨两个 tab（日程 ⇄ 待办）时中间的课表页会快速扫过；
2. **先快后慢的减速曲线**：`tween(TabTransitionMillis, LinearOutSlowInEasing)`（时长当前 400ms）——位移是直线平移，起点即全速、此后单调减速收尾。中途试过物理弹簧（阻尼/刚度可调、时长随距离自适应、连点用当前速度续跑），实机观感被否决；尤其注意 `FastOutSlowInEasing` 与这里的诉求**相反**：那条约前 30% 是加速段（起步偏肉），是"先慢后快再慢"；
3. **仅点按触发**，不加 tab 间滑动手势——既避免与课表「内容区左右滑动翻周」抢手势，也免掉外层可滚动容器的嵌套。

## 实现（仅 `MainActivity.kt`）

`offscreenWhenHidden`（把非选中页硬放到 `width * 2`）→ `tabPage`，且位移**拆成"布局槽位 + layer 追赶"两半**（拆的原因见下面的帧率一节）：

```kotlin
// tab 平移进度（浮点序号）：只在各页布局/layer 阶段被读取，动画期间不重组
val tabProgress = animateFloatAsState(
    targetValue = selectedTab.ordinal.toFloat(),
    animationSpec = tween(durationMillis = TabTransitionMillis, easing = LinearOutSlowInEasing),
    label = "tabProgress",
)

private fun Modifier.tabPage(tab: AppTab, selectedTab: AppTab, progress: State<Float>): Modifier {
    val target = selectedTab.ordinal
    // 布局槽位：永远是"最终"位置（选中页 0，其余 ±N 屏）——命中测试/滚动/语义都归布局管
    val placed = this.layout { measurable, constraints ->
        val placeable = measurable.measure(constraints)
        val slotX = (tab.ordinal - target) * placeable.width
        layout(placeable.width, placeable.height) { placeable.place(slotX, 0) }
    }
    // layer 追赶：只承担动画中的位移（起始 ±N 屏 → 收尾 0），只更新变换矩阵
    val animated = placed.graphicsLayer {
        translationX = ((target - progress.value) * size.width).roundToInt().toFloat()
    }
    return if (tab == selectedTab) animated else animated.clearAndSetSemantics {}
}
```

两半相加 = 视觉上的连续带子：`(序号 − 目标) × 页宽 + (目标 − 进度) × 页宽 = (序号 − 进度) × 页宽`。

## 帧率：为什么不能只用布局位移

第一版是纯布局位移（`layout` + `place()`，按 `(序号 − 进度) × 页宽` 定位），观感对但掉帧。原因是**这三个页面没有自己的图层**：所有绘制指令都录在同一份父层里，页面位置一变，父层就得把三页的绘制指令整段重录——课表页含日期带 + 三个周页 × 每行五格卡片，一帧重录一次就是掉帧的来源（静止时也一样，三页的指令每帧都在重放，离屏页也剔不掉）。

现在：

- **每帧只更新 layer 的变换矩阵**：子树布局、绘制指令、文字排版一概不动，也不触发重组/重排；
- **每页各有一层**后，离屏页可被 HWUI 整层剔除；
- 布局槽位在**点击那一刻**才变一次（由 `selectedTab` 决定，与动画无关），所以布局既不参与逐帧动画，也不会因为动画产生额外重录；
- 交互仍由布局说了算：选中页的槽位就是屏幕位置，离屏页的槽位在屏幕外 —— 与改造前完全一致，旧页滑出过程中也不会抢到点击。

要点：

1. **动画值以 `State<Float>` 传入、在布局/layer 阶段读取**：若在组合作用域里读出来再当参数传，每帧会重组整个内容 lambda（连带三个页面的调用点）。
2. **平移取整到整像素**：动画期间文字不糊；收尾 `progress` 精确等于目标值，`translationX` 归 0，与原位逐像素重合。
3. **三页常驻组合**不变（原有注释随 helper 迁移）：切 tab 不重建，避免课表页首帧 `headerHeight` 回落到估算值、紧贴头部的日期带跳闪一次；滚动位置、折叠状态、当前周次全部存活。
4. **首帧不补播动画**：`animateFloatAsState` 初值即目标值，冷启动/进程重建后各页直接落在各自位置；`selectedTab` 仍是 `rememberSaveable`。
5. 非选中页仍 `clearAndSetSemantics {}`（离屏页对 TalkBack 隐藏）。
6. 新增导入：`animation.core.{animateFloatAsState, tween, LinearOutSlowInEasing}`、`runtime.State`、`ui.graphics.graphicsLayer`、`kotlin.math.roundToInt`。

## 备注

1. **带子模型只有一条时间轴**：三页共享同一个进度值，任意时刻的位移都由它决定。所以在"连续平移"下，动感能调的只有这条曲线本身（弹簧 / 贝塞尔）；想让两页节奏不同（旧页加速滑出、新页减速滑入）或叠加视差，必须改成每页各自驱动，即放弃刚性带子。
2. 跨两 tab 时中间页扫过是连续带子的必然结果。若观感上不想要，可改为 shared axis 风格（旧页滑出一屏、新页滑入一屏、中间页不出场），代价是每页各自的方向与层级/显隐处理；随时可换。
3. 另一个方向：Material 对底部导航切 tab 的官方推荐转场是 FadeThrough（淡出淡入 + 92% 缩放，不平移），若某天想要"高级感"而非"平移感"，那是比调曲线更彻底的答案。
