# 课表数据层（"后端"）实现计划

## 需求回顾（7 条）

1. 多课表可切换；每课表有起止：起始=第一周周一，终止=最后一周的周五（或周日）。
2. 课表可分享保存。
3. 默认周一至周五有课，课表级设置可改为周一至周日（视图调整属后续 UI 批次）。
4. 默认每天 5 节大课；一节课连续占用 1-5 节大课（跨节次）；用户可调整每天节数。
5. 每节大课有起止时间，默认 8:00-9:40 / 10:10-11:50 / 14:30-16:10 / 16:40-18:20 / 19:10-20:50（时长默认相同），可逐节调整。
6. 课程五要素：名称、教师、地点、卡片颜色、上课周数（支持单双周）；同一位置（同一天且 span 相交）的课程周数不得重叠。
7. 本周不上的课是否显示为课表级全局开关；显示时卡片色 `#cbcbcb`、课名色 `#737a83`（灰显是 UI 关注点，本批只暴露开关 + "某课某周是否活跃"查询）。

## 已确认决策（用户拍板，不可改）

| 决策 | 选择 |
|---|---|
| 范围 | **仅数据层**。`ui/**` 一个文件不动，继续吃 MockCourses；新旧模型在 `data.*` 与 `ui.schedule` 暂时并存 |
| 持久化 | JSON 单文件 + kotlinx.serialization（不引入 Room/DataStore） |
| 分享 | JSON 文本导出/导入的数据层 API（不写 Intent/UI） |
| 设置归属 | 学期起止、daysPerWeek、节数与各节时间、置灰开关全部是 `Schedule` 的字段（每课表一套） |
| 置灰开关 | 课表级布尔 `showInactiveCourses`（默认 true=显示并置灰） |

- `app/build.gradle.kts:1-5` 只有 `android.application` + `kotlin.compose` 插件（AGP 9 内建 Kotlin，无 kotlin-android 行）；无任何序列化/存储依赖。
- 现有 UI 期望 `List<Course>` + `List<TimeSlot>`（`CourseGrid.kt:67-75`），且 `CourseGrid.kt:187` 硬编码 `for (day in 1..5)`、`ScheduleScreen.kt:49-51` 直接 `remember { MockCourses }` —— 均本批不动。

## 核心设计决定

| 项 | 选择 | 理由 |
|---|---|---|
| id | `String` UUID | 导入时整体重铸即保证零冲突，无需协调 |
| 周数 | `WeekPattern { segments: List<WeekSegment(start,end,parity=ALL/ODD/EVEN)> }` | 覆盖单双周、跳周多段；JSON 紧凑可读；求交是纯整数运算 |
| 跨节次 | `startSlot`(1-based) + `span`(1..5)，`endSlot=startSlot+span-1` | 需求明示上限 5；节次列表**位置即 id**（不存 slot id，消除 id 与节数不同步问题） |
| 日期 | JSON 存 `yyyy-MM-dd` 字符串，内部 `IsoDate(epochDay: Long)` + 自定义 Serializer | 整数运算做周计算；绕开 minSdk 24 无 java.time；周几用公式 `((epochDay+3)%7+7)%7+1`（1=周一…7=周日） |
| 时间 | `"8:00"` 字符串与现有 UI 一致；校验正则 `^([01]?\d|2[0-3]):[0-5]\d$`，写入前归一化为无前导零；比较用分钟数 | 兼容现有 mock 形态 |
| 版本 | 存储文件与分享信封都带 `formatVersion: Int = 1` | 存储演进；导入拒绝更高版本 |

## 数据模型骨架（`data/model/`）

```kotlin
// IsoDate.kt
@Serializable(with = IsoDateSerializer::class)
data class IsoDate(val epochDay: Long) {
    operator fun plus(days: Int): IsoDate
    operator fun minus(other: IsoDate): Long        // 天数差
    fun isoDayOfWeek(): Int                        // 1=周一 … 7=周日，纯公式
    companion object { fun parse(s: String): IsoDate }   // 严格 yyyy-MM-dd，GregorianCalendar(UTC) 校验真实日期（闰年）
    companion object { fun today(millis: Long): IsoDate } // 默认时区 → 本地日历 → epochDay
}

// ScheduleModels.kt
const val SCHEDULE_FORMAT_VERSION = 1
@Serializable enum class Parity { ALL, ODD, EVEN }
@Serializable data class WeekSegment(val start: Int, val end: Int, val parity: Parity = Parity.ALL)
@Serializable data class WeekPattern(val segments: List<WeekSegment> = emptyList()) {
    fun contains(week: Int): Boolean                // 任一段命中（并集）
    fun intersects(other: WeekPattern): Boolean     // 段级区间相交 && 奇偶可同时命中（ALL 与任何相容）
}
@Serializable data class TimeSlotDef(val startTime: String, val endTime: String)
@Serializable enum class CourseColor { Blue, Green, Greentwo, Yellow, Orange, Purple, Teal, Pink }
//   ↑ 条目名与 ui.schedule.CourseColor 完全一致，后续 UI 映射只需 valueOf()

@Serializable
data class CourseEntry(
    val id: String, val name: String, val teacher: String, val location: String,
    val dayOfWeek: Int,          // 1..daysPerWeek
    val startSlot: Int, val span: Int = 1,          // span ∈ 1..5
    val weeks: WeekPattern, val color: CourseColor,
) { val endSlot: Int get() = startSlot + span - 1 }

@Serializable
data class Schedule(
    val id: String, val name: String,
    val termStart: IsoDate,       // 第一周周一
    val termEnd: IsoDate,         // 最后一周周五(或周日)
    val daysPerWeek: Int = 5,     // 5 | 7
    val slots: List<TimeSlotDef> = DEFAULT_SLOTS,  // size 即节数
    val courses: List<CourseEntry> = emptyList(),
    val showInactiveCourses: Boolean = true,        // 置灰开关（课表级）
) {
    val totalWeeks: Int get() = ((termEnd - termStart).toInt() / 7) + 1
    val slotCount: Int get() = slots.size
}

val DEFAULT_SLOTS = listOf(TimeSlotDef("8:00","9:40"), TimeSlotDef("10:10","11:50"),
    TimeSlotDef("14:30","16:10"), TimeSlotDef("16:40","18:20"), TimeSlotDef("19:10","20:50"))

/** 调整节数时的默认生成：N≤5 取前 N 条；N>5 在末节后按"间隔30分钟、时长100分钟"顺延（启发式，调用方/UI 可再改） */
fun defaultSlotsFor(count: Int): List<TimeSlotDef>

// ScheduleFile.kt（存储信封）
@Serializable data class ScheduleFile(
    val formatVersion: Int = SCHEDULE_FORMAT_VERSION,
    val activeScheduleId: String? = null,           // "切换课表"持久化锚点
    val schedules: List<Schedule> = emptyList(),
)
// SharePayload.kt（分享信封）
@Serializable data class SharePayload(
    val formatVersion: Int = SCHEDULE_FORMAT_VERSION,
    val kind: String = "classpp.schedule",          // 防误导入其他 JSON
    val exportedAtMillis: Long,
    val schedule: Schedule,                         // 导入方会重铸 id
)
```

日期/周计算约定：学期合法 ⇔ `start.isoDayOfWeek()==1`、`end.isoDayOfWeek() ∈ {5,7}`、`end≥start`、`(end-start) % 7 ∈ {4,6}`；`weekOf(d)=(d-termStart)/7+1`；`datesForWeek(w) = (0 until daysPerWeek).map { termStart + (w-1)*7 + it }`。

## 校验规则（`ScheduleValidator`，纯函数，返回全部错误非 fail-fast）

| # | 规则 | 错误 |
|---|---|---|
| R1 | termStart 必须周一 | `TermNotMonday` |
| R2 | termEnd 必须周五/周日 | `TermEndInvalid` |
| R2b | `daysPerWeek==7 ⇒ termEnd 必为周日`（否则末周周末日期越界）；`daysPerWeek==5` 时周五/周日均可 | `TermEndInvalid` |
| R3 | `end≥start` 且 `(end-start)%7 ∈ {4,6}` | `TermRangeInvalid` |
| R4 | `daysPerWeek ∈ {5,7}` | `DaysPerWeekInvalid` |
| R5 | `slotCount ∈ 1..12`（国内高校 ≤12 大节；拦手改 JSON 的 999；下限 1 防空） | `SlotCountInvalid` |
| R6 | 每节时间匹配正则 | `SlotTimeFormatInvalid` |
| R7 | 每节 `startMin<endMin` 且有序不重叠（`prev.end≤next.start`，允许紧贴） | `SlotOrderInvalid` |
| R8 | 课表名非空白 | `InvalidScheduleName` |
| R9-R12 | 课程：名非空白 / `dayOfWeek∈1..daysPerWeek` / `startSlot∈1..slotCount && span∈1..5 && endSlot≤slotCount` / weeks 每段 `1≤start≤end≤totalWeeks` | `CourseFieldInvalid` / `WeekSegmentInvalid` / `WeeksBeyondTerm` |
| R13 | **同格周数重叠**：按 day 分组，组内两两判断 `span相交 && weeks相交` → 冲突 | `GridConflict(day, a, b)` |

R12 算法：`span相交 = a.startSlot<=b.endSlot && b.startSlot<=a.endSlot`（含包含、共用端点节次；**端点相接不算**）；`weeks相交` = 段区间重叠且奇偶可同时命中。不同天不算冲突。

**设置变更导致已有课程非法 → 拒绝 + 结构化错误，绝不静默删除**：`setTerm/setDaysPerWeek/setSlots` 均"构造候选 → validate → 有错整体拒绝返回 `CoursesOutOfRange(affected: List<CourseRef>)`，内存与磁盘零变更"。理由：课程数据不可再生，静默删是不可逆损失；结构化错误让后续 UI 能提示"以下 N 门课超范围，请先处理"。

错误类型：`sealed class ScheduleError`（TermNotMonday / TermEndInvalid / TermRangeInvalid / DaysPerWeekInvalid / SlotCountInvalid / SlotTimeFormatInvalid / SlotOrderInvalid / InvalidScheduleName / InvalidCourseName / CourseFieldInvalid(reason 枚举) / WeekSegmentInvalid / WeeksBeyondTerm / GridConflict / CoursesOutOfRange / NotFound / ImportFormatInvalid / ImportVersionUnsupported / ImportKindMismatch / PersistFailed）。

## 存储层（`data/store/ScheduleStore.kt`）

**单文件 `filesDir/schedules.json`**（含 activeScheduleId，与课表列表原子一致；课表量级个位数、KB 级；一次 tmp+rename 整库提交）。接口（阻塞实现，由仓库包 IO 调度器）：

```kotlin
interface ScheduleStore { fun load(): LoadOutcome; fun save(file: ScheduleFile): StoreResult }
sealed class LoadOutcome {
    data class Loaded(val file: ScheduleFile, val issue: LoadIssue = LoadIssue.None): LoadOutcome()
    data class Fresh(val file: ScheduleFile, val issue: LoadIssue): LoadOutcome()   // 首装或全损坏
}
enum class LoadIssue { None, RestoredFromBackup, ResetAfterCorruption }
```

- save：写 `schedules.json.tmp`（fsync）→ 旧主文件复制为 `.bak` → `rename` 覆盖；任一步失败返回 `Failed`。
- load 降级：主文件坏 → 试 `.bak`（成功=RestoredFromBackup，不覆盖坏文件）→ 双坏则主文件改名 `schedules.corrupt-<millis>.json` 保留取证 + Fresh(ResetAfterCorruption)；`formatVersion>1` 同损坏处理；主文件不存在=Fresh(None)。

## 仓库层（`data/ScheduleRepository.kt`）

形态：**StateFlow 读 + suspend 写 + Mutex 事务**（校验→改内存→落盘→失败回滚），无 DI 框架：

```kotlin
class ScheduleRepository internal constructor(private val store: ScheduleStore, private val clock: Clock) {
    val schedules: StateFlow<List<Schedule>>
    val activeScheduleId: StateFlow<String?>
    val activeSchedule: StateFlow<Schedule?>          // combine 而来
    val loadState: StateFlow<LoadState>               // Ready / RestoredFromBackup / ResetAfterCorruption

    suspend fun createSchedule(name, termStart, termEnd, daysPerWeek=5, slots=DEFAULT_SLOTS): ReadResult<String>
    suspend fun renameSchedule(id, name): OpResult
    suspend fun deleteSchedule(id): OpResult           // 删激活项→落到剩余第一个；删空→null；文件保留
    suspend fun setActiveSchedule(id): OpResult        // 无 DI 入口见下

    suspend fun setTerm(id, start, end): OpResult
    suspend fun setDaysPerWeek(id, days): OpResult     // 7→5 有周末课 → CoursesOutOfRange
    suspend fun setSlots(id, slots): OpResult          // 减节次尾部有课 → CoursesOutOfRange
    suspend fun setShowInactiveCourses(id, show): OpResult   // 无课影响，恒 Ok

    suspend fun upsertCourse(scheduleId, course): OpResult   // 新课由调用方带新 UUID 或仓库补；提交前跑全量校验（含 R13）
    suspend fun removeCourse(scheduleId, courseId): OpResult
    suspend fun removeCourses(scheduleId, courseIds): OpResult

    fun coursesForWeek(scheduleId, week): List<CourseOccurrence>     // 越界周 → []，不抛错
    fun courseAt(scheduleId, week, day, slot): CourseOccurrence?
    fun visibleCoursesForWeek(scheduleId, week): List<CourseOccurrence>  // 应用 showInactiveCourses 过滤
    fun datesForWeek(scheduleId, week): List<IsoDate>               // daysPerWeek 个
    fun termPosition(scheduleId, today=clock.today()): TermPosition  // BeforeTerm / InTerm(week) / AfterTerm
    fun currentWeek(scheduleId): Int?                                // 学期外 null

    suspend fun exportSchedule(id): ReadResult<String>               // pretty JSON 文本
    suspend fun importSchedule(json): ReadResult<String>             // Ok=新课表 id

    companion object {
        suspend fun create(store: ScheduleStore, clock: Clock = SystemClock): ScheduleRepository  // 构造时 load 灌 StateFlow
        fun get(context: Context): ScheduleRepository      // 进程级懒加载单例（首次调用内部完成 load）
    }
}
data class CourseOccurrence(val course: CourseEntry, val active: Boolean, /* weeks.contains(week) */)
```

`Clock`：`fun interface Clock { fun today(): IsoDate }`（测试注入 FakeClock）。

与 mock 对应（后续 UI 迁移替换点）：`MockCourses/findAt` → `visibleCoursesForWeek/courseAt`；`DefaultTimeSlots` → `schedule.slots`；`TermStart/datesForWeek` → `schedule.termStart` + 仓库版 `datesForWeek`；`Course.slotId` → `startSlot+span`。

## 分享（`data/export/ShareCodec.kt`）

导出 `SharePayload` pretty-print JSON（`activeScheduleId` 不进载荷）。导入流程：

1. 解析失败 → `Err(ImportFormatInvalid)`（不落盘）；
2. `formatVersion>1` → `ImportVersionUnsupported`；`kind!="classpp.schedule"` → `ImportKindMismatch`；
3. **id 重铸**：schedule.id 与全部 course.id 一律重新生成 UUID（冲突保证的唯一机制，不依赖比对）；
4. 全量 validate → 有错拒绝、库零变更；
5. 名称冲突自动后缀 `"名 (导入)"`/`"(导入 2)"`（不阻断）；
6. 追加落盘；**不切换 activeScheduleId**（不劫持当前视图）；`Ok(新id)`。
