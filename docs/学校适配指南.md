# 学校适配指南（多学校「账号与同步」）

> 适用对象：为本仓库接入一所新的学校（待办同步 / 网页登录 / 原生登录 / 教务课表导入）。
> 通用工具包位于 `data/sync/`，厦大（`data/xmu/` + `schools/xmu/`）是参考实现。
>
> **纪律**（继承《实施指导-多学校账号同步适配》§五 / `docs/AGENTS.md`）：
> - 本仓库禁止模拟器/真机验证；验收 = 编译 + 单测 + 静态守卫 + 评审清单；
> - 真实学校账号联调由适配开发者自行完成（Phase 5），不要把真机步骤写进本仓库测试；
> - `data/xmu/` 是冻结层：不要为了接新校修改它；通用层不得 import `data.xmu`；
> - 任何存储位置改动必须与 `backup_rules.xml` / `data_extraction_rules.xml` 同提交。

## 0. 一页总览

```
schools/<id>/                 # 一校一文件夹，自包含
├─ <Id>SchoolProvider.kt      # SchoolProvider：声明 spec + 装配 session
├─ <Id>SyncCodec.kt           # SyncCodec：远端协议 → Todo
├─ <Id>SessionApi.kt          # 可选：原生取数（实现 SessionApi）
└─ <Id>LoginClient.kt         # 可选：原生登录（实现 LoginClient）

data/sync/                    # 通用层（学校无关，不要往里写学校逻辑）
├─ SchoolSpec / SchoolText / SchoolSession / SchoolRegistry / SyncTypes
├─ engine/   SyncCodec、SchoolSyncEngine、SchoolSyncStore
├─ credential/ SchoolSecureStore、KeystoreCipher、AutoRenewManager、AutoRenewSessionRouter
├─ webview/  WebViewPolicy、WebSessionDriver、WebFetcher
├─ net/      HttpTransport、OkHttpTransport、CookieMirror、SessionCookieHolder
├─ media/    AvatarCache、HttpAvatarFetcher
└─ remote/   远端声明学校（Tier 1）：SchoolDeclaration、DeclarativeSyncCodec、
             RemoteSchoolProvider、SchoolRemoteCatalog、RemoteSchoolPrefs、
             SchoolDailySyncReceiver（分发链路，见 §10）

ui/schools/                   # 通用 UI 绑定
├─ SchoolUiBindings.of(session) → 已注册自定义 UI 或 GenericSchoolUi
├─ GenericSchoolUi            # 纯声明学校的零代码 WebView 登录浮层
└─ SchoolTexts.schoolText()   # SchoolText.Res/Inline 的 Compose 解析入口
```

能力槽位与声明必须一致（注册表装配后硬校验）：

| 能力 | 会话槽位 | UI 表现 |
| --- | --- | --- |
| `NATIVE_LOGIN` | `autoRenew: AutoRenewService` | 凭据浮层 + 自动续期开关 |
| `WEBVIEW_LOGIN` | `webViewLogin: WebViewLoginSpec` | 网页登录入口（含备用登录方式） |
| `SCHEDULE_IMPORT` | `scheduleImport: ScheduleImportService` + `timetableIntro` | 教务导入入口/介绍卡 |

至少声明一种登录能力；`timetableIntro` 必须与 `SCHEDULE_IMPORT` 成对出现。

可选槽位 `ScheduleImportService.webViewTimetable: WebViewTimetableSpec?`：声明教务课表页
（入口 URL / 白名单 / UA）。WebView 登录模式（已连接但没有保存凭据，
`ImportBlockReason.NoCredentials`）下，教务导入浮层会在「账号与同步」卡下方显示
「从教务网页导入」入口，点击打开该页面；不声明则只保留原生凭据导入。声明该槽位要求
学校同时具备 `WEBVIEW_LOGIN`，页面声明与 `WebViewLoginSpec` 走同一套
`WebViewPolicy` 硬校验（仅 https/默认端口/白名单域，加固无法关闭）。

网页导入分两段，缺一不可：`WebViewTimetableSpec.importScript` 由学校适配层提供，在
已登录的课表页上下文执行（约定把抓取结果 JSON 原文写回
`WebViewTimetableJs.RESULT_VAR`，原生侧轮询取回——`evaluateJavascript` 不等待
Promise）；原文交给 `ScheduleImportService.importFromWebTimetable(raw)` 解析成课表，
落库仍走 UI 的既有确认 + 仓库导入路径。不提供 `importScript` 时页面只浏览、不显示
导入按钮。

接入方式两条：**编译期适配**（§1–§5，支持全部能力）与**远端声明**（§10，Tier 1：
仅 WebView 登录 + JSON 待办，零发版）。新校优先评估能否用远端声明。

## 2. 选登录方式

### 2.1 只做 WebView（推荐给不想接触密码的学校）

填 `WebViewLoginSpec`，**不写任何 UI 代码**：`GenericSchoolUi` 会自动接手登录浮层，
`WebFetcher` 负责已连接后的无头取数。

```kotlin
internal val ABC_WEB_VIEW = WebViewLoginSpec(
    entryUrl = "https://lms.abc.edu.cn/user/index?version=v1",
    allowedHosts = setOf("lms.abc.edu.cn", "ids.abc.edu.cn"),
    dataHost = "lms.abc.edu.cn",
    profilePath = "/api/profile",
    todosPath = "/api/todos",
    userAgent = DESKTOP_UA,   // null = 系统默认
)
```

校验规则（注册表装配时硬校验，`WebViewPolicy.validate`）：
- 入口 URL 必须 https、默认 443、无 userinfo、host ∈ `allowedHosts`；
- `allowedHosts` 只允许小写域名（至少一个点），禁 IP 字面量 / 通配符 / 显式非 443 端口；
- `dataHost ∈ allowedHosts`；不同学校的白名单**不得重叠**（共用 CAS 域会让 cookie 互串）；
- `profilePath` / `todosPath` 必须是 `/` 开头的安全路径（禁引号/反斜杠/空白，防 JS 注入）；
- 加固项（禁 file/content、禁混合内容、SSL 拒错、白名单导航）锁死在 `WebViewPolicy`，
  spec 无法关闭。

登录态确认口径（profile 正文有效性）：默认「JSON 对象」；建议在会话上注入更严格的
校验（如必须含非空 uid），避免 200 的登录页 JSON 被误判为已登录：

```kotlin
override val webViewProfileValidator: ((String) -> Boolean)? = { raw ->
    runCatching { ScheduleJson.decodeStorage<AbcProfileDto>(raw).id > 0 }.getOrDefault(false)
}
```

### 2.2 原生登录 + 自动续期（可选）

实现两件事：

1. `LoginClient`：账号密码 → 会话凭据（用 `HttpTransport` 发请求，密码只提交给学校声明的身份主机）；
2. `SessionApi`：会话 → `LoginRaw(profileRaw, todosRaw)`（解析交给 codec）。

```kotlin
internal class AbcLoginClient(
    private val transport: HttpTransport,
) : LoginClient {
    override suspend fun login(username: String, password: String): LoginResult {
        // …CAS/Keycloak 链路…
        return try {
            LoginResult.Ok(LoginSession(cookieHeader = "sid=$sid", cookies = mapOf("sid" to sid)))
        } catch (e: SocketTimeoutException) {
            LoginResult.Timeout
        } catch (e: IOException) {
            LoginResult.NetworkError
        }
    }
}

internal class AbcSessionApi(
    private val transport: HttpTransport,
    private val cookies: SessionCookieHolder,
) : SessionApi {
    override suspend fun fetchSession(): FetchOutcome {
        // 带 cookies.header 请求 profile/todos；按状态码分类：
        // 302→登录页 / 401 / 403 = SessionExpired；5xx = ServiceBusy；IO = NetworkError；
        // 200 但结构不符 = FormatChanged
    }
}
```

装配 `AutoRenewManager`（单飞 / 失败即停 / 60 秒退避全部已封装）：

```kotlin
val autoRenew = AutoRenewManager(
    store = SchoolSecureStore(appContext, "abc"),   // sync_secure.xml，按校分键
    loginClient = AbcLoginClient(OkHttpTransport(userAgent = DESKTOP_UA)),
    sessionApi = abcApi,
    cookieHolder = SessionCookieHolder(),
    cookieMirror = AndroidCookieMirror,             // 关闭自动续期后网页仍可复用会话
    mirrorHost = ABC_WEB_VIEW.dataHost,
    logger = SyncDebugLog::d,
).also { it.bootstrap() }
```

路由（原生优先、WebView 兜底）直接复用：

```kotlin
val api: SessionApi = AutoRenewSessionRouter(autoRenew, WebFetcher(appContext, ABC_WEB_VIEW, validator))
```

> 不想保存密码就不要声明 `NATIVE_LOGIN`：UI 会自动隐藏自动续期相关行。

## 3. 实现 `SyncCodec`（同步的核心）

```kotlin
internal class AbcCodec(private val clock: () -> Long) : SyncCodec<AbcRemoteTodo> {

    override val source: String = "abc"      // 必须等于 spec.id

    // 确定性本地 id：重复同步天然幂等；必须以 "<id>-" 开头
    override fun localId(remoteKey: String): String =
        remoteKey.removePrefix("abc:").split(':').let { (courseId, id) -> "abc-$courseId-$id" }

    override fun matchesLocalId(id: String): Boolean = id.startsWith("abc-")

    override fun parseProfile(raw: String): RemoteProfile?  // uid / accountName / avatarUrl
    override fun parseTodos(raw: String): List<AbcRemoteTodo>?  // 结构不符返回 null

    override fun remoteKey(remote: AbcRemoteTodo): String = "abc:${remote.courseId}:${remote.id}"
    override fun remoteHash(remote: AbcRemoteTodo): String  // 只落哈希，不存标题原文
    override fun toTodo(remote: AbcRemoteTodo, fetchedAt: Long): Todo?  // null = 跳过
    override fun skipReason(remote: AbcRemoteTodo): SkipReason?         // 锁定/过期/非法…
    override fun autoGroupKey(remote: AbcRemoteTodo): String? =
        if (remote.type == "homework") "abc:homework" else null
    override fun isOwned(todo: Todo): Boolean =
        todo.source == source || matchesLocalId(todo.id)
}
```

要点：
- **远端唯一键** = 校内唯一（如 `courseId + activityId`）；entries 映射与去重都按它配对；
- `remoteHash` / `localHash` 只存哈希；不要往状态文件写标题/课程名原文；
- `skipReason` 与 `toTodo` 的契约：`skipReason == null` 时 `toTodo` 应非 null；
  接口形态变化导致的「非空但解析失败」请用 `SkipReason.DeadlineUnparseable` 单独计数；
- 过期判定需要「现在」时，由构造注入时钟（引擎只把 `fetchedAt` 传给 `toTodo`）。

## 5. 装配 `SchoolProvider`

```kotlin
class AbcSchoolProvider : SchoolProvider {

    override val spec: SchoolSpec = ABC_SPEC

    @Volatile private var toggle: DailySyncToggle? = null

    // 后台重排只读开关，不装配完整 session：provider 级与 session 级必须是同一实例/同一存储
    override fun dailySyncToggle(context: Context): DailySyncToggle =
        toggle ?: synchronized(this) {
            toggle ?: PrefsDailySyncToggle(context.applicationContext, spec.id).also { toggle = it }
        }

    override suspend fun createSession(deps: SessionDeps): SchoolSession {
        val context = deps.appContext
        // …按 §2/§3/§4 装配…
        return AbcSession(
            spec = spec,
            sync = engine,
            autoRenew = if (Capability.NATIVE_LOGIN in spec.capabilities) autoRenew else null,
            scheduleImport = null,   // 实现了教务导入再填
            webViewLogin = if (Capability.WEBVIEW_LOGIN in spec.capabilities) ABC_WEB_VIEW else null,
            dailySync = dailySyncToggle(context),
            webViewProfileValidator = ::isAbcProfile,
        )
    }
}
```

注册（唯一装配点）：`AppContainer.schoolProviders()` 列表加一行。

```kotlin
private fun schoolProviders(): List<SchoolProvider> = listOf(
    XmuSchoolProvider(),
    AbcSchoolProvider(),   // ← 新校
)
```

UI：声明了 `WEBVIEW_LOGIN` 的学校由 `SchoolUiBindings.of(session)`
统一落到 `GenericSchoolUi`（厦大已并入该路径，零学校分支），**无需写任何 UI 代码**。
只有需要特殊页面结构/交互时才注册自己的 `SchoolUi` 实现（当前无注册项）。

每日同步：通用 `DailySyncScheduler` / `DailySyncRunner` / `SchoolDailySyncController`
自动作用于活跃学校，开关来自 `session.dailySync`；到点广播锚点由
`SchoolProvider.dailySyncFireIntent` 声明（接收类 + requestCode + action 是已发布闹钟的
冻结锚点，锁在学校自己的薄壳/适配层里；返回 null = 本校不参与每日同步闹钟）。参考厦大
`XmuSchoolProvider`（冻结 receiver `XmuDailySyncAlarmReceiver` 的工厂）。

远端声明学校（Tier 1）**共享同一个通用锚点** `SchoolDailySyncReceiver`
（requestCode 2002，与厦大 1001 区分）：同一时刻只有一个活跃学校、一个闹钟位，
换校时的锚点切换由 `SchoolDailySyncController` 的 `SyncAlarmAnchorSwap` 兜住。
系统事件（开机/时间/时区/日期）的重排仍由厦大冻结 receiver 全局承担，通用 receiver
只处理调度器自己发出的显式 `ACTION_FIRE`（manifest `exported=false`，无 intent-filter）。

## 9. 常见问题

**Q：`schools/<id>` 可以 import `data/xmu` 吗？**
只有厦大适配层可以（冻结协议是它的实现）。新校不得依赖 `data/xmu`，否则架构守卫会失败；
加密/原子写/WebView 加固等通用能力都已在 `data/sync` 提供等价实现。

**Q：能不做 WebView、只做原生登录吗？**
可以。声明 `NATIVE_LOGIN`、`webViewLogin = null`，UI 不显示网页登录入口。但自动续期失败
（验证码/改版）后没有兜底路径，用户只能重输密码——产品上需接受这一点。

**Q：教务课表导入必须实现吗？**
不必。不声明 `SCHEDULE_IMPORT` / 不提供 `scheduleImport` 时，`ScheduleScreen` 自动隐藏入口。

**Q：头像必须提供吗？**
可选。不传 `AvatarCache` 或不提供 `avatarUrl` 时 `avatarImage` 恒为 null，UI 走姓名首字占位。

**Q：每日自动同步会自动支持新校吗？**
会。`DailySyncRunner` 只作用于活跃学校，开关读 `session.dailySync`（`sync_prefs` 按校分键），
切校后闹钟自动重排。非活跃学校不参与（选择浮层会提示）。

## 10. 远端声明学校（Tier 1，零发版接入）

「WebView 登录 + JSON 待办接口」类学校可以**不写代码**接入：服务器下发一份 JSON 声明，
用户在设置页**手动更新**后注册。**新校接入 = 远端仓库加一个 JSON 文件，零发版。**

> 远端学校**默认关闭**，拉取是纯手动操作：App 启动/后台/定时都不会访问远端仓库。
> 用户在学校选择浮层点击「更新远端学校列表」后，声明会下载并保存到本地，
> 之后每次冷启动从本地缓存恢复（仍不会自动联网更新）。

### 10.1 适用范围与信任边界

- 仅支持 `WEBVIEW_LOGIN`（能力声明必须恰为 `["WEBVIEW_LOGIN"]`）：没有原生登录/自动续期
  （这两类仍走 §1–§5 的编译期适配）。
- 可选 `timetable` 块支持 **WebView 教务课表导入**：声明课表页入口、页面学期选择器、
  同源接口与字段路径；App 用固定脚本取数、通用映射器生成课表。`capabilities` 仍写
  `["WEBVIEW_LOGIN"]`——旧客户端忽略该块、继续同步待办，新客户端据此启用导入。
- **所有 host 必须以 `.edu.cn` 结尾**（`allowedHosts`、`dataHost`、头像 `cookieHosts`、
  `timetable.allowedHosts`）；`edu.cn` 本身、`foo.edu.cn.evil.com` 这类伪装域一律拒绝。
- 远端白名单不再来自编译期代码，因此**首次连接某所远端学校会弹确认浮层**（展示学校名、
  登录域与可选课表页域），确认后才切校；记录在 `remote_sync_prefs` 的
  `remote/<id>/confirmed`。

### 10.2 分发链路（`data/sync/remote/`）

| 组件 | 职责 |
| --- | --- |
| `SchoolDeclaration` | JSON schema（index + 单校）+ `validate()` 硬校验；`toSpec()` 生成全 Inline 文案的 `SchoolSpec`（`remote = true`） |
| `DeclarativeSyncCodec` | 声明式 `SyncCodec<JsonObject>`：dot-path、模板、跳过规则、ISO/PATTERN 时间、自动分组 |
| `RemoteSchoolProvider` | 声明 → `SchoolSpec` + `SchoolSyncEngine` + `WebFetcher` + `AvatarCache`；共享通用闹钟锚点 |
| `SchoolTimetableDeclaration` | 可选 `timetable` 块的 schema/硬校验（接口、字段路径、位图、开学日） |
| `RemoteTimetableScript` | 由声明生成固定 ES5 抓取脚本（不接收远端 JS） |
| `RemoteTimetableMapper` | 回传原文 → `Schedule`（位图周次、拆行合并、开学日推算） |
| `RemoteScheduleImportService` | WebView-only 的 `ScheduleImportService`（连接后 `NoCredentials`） |
| `SchoolRemoteCatalog` | 拉取 index → 逐校文件 → 校验 → 写 `filesDir/sync_remote/`；`loadCached()` 离线可用 |
| `RemoteSchoolPrefs` | `remote_sync_prefs`：按校首次连接确认记录（无总开关） |
| `RemoteSchoolManager` | 用户侧入口：首次确认 + `refresh()`（**仅手动点击触发**，下载并落盘；无开关） |
| `SchoolDailySyncReceiver` | 全部远端校共享的到点 receiver（requestCode 2002，manifest `exported=false`） |

启动与更新（**远端学校默认关闭**）：

1. 冷启动（`AppContainer.create`）：**只读本地缓存**恢复手动更新过的远端校（不联网）；
   从未手动更新（无缓存）时注册表只有编译期学校 = 默认关闭；
2. 用户在学校选择浮层点击「更新远端学校列表」（`RemoteSchoolManager.refresh`）：拉取清单
   与声明并落盘，新 id 经 `SchoolRegistry.registerRemote` 合并（`schools` 是 `StateFlow`，
   选择器自动更新）；失败保留缓存并由 UI 提示；
3. 手动更新成功后声明保存在本地，重启后从缓存恢复；已注册校的声明变更不热更新
   （再次手动更新写入新缓存，重启后生效）。

### 10.3 声明内容（权威文档在 `tools/schoolsync/README.md`）

- `webView`：`entryUrl` / `allowedHosts` / `dataHost` / `profilePath` / `todosPath` / `userAgent`；
- `copy`：9 个必填文案 + 7 个可空覆盖（省略 = `sync_*` 中性键）；
- `profile`：`uidPath`（非空即已登录）/ `namePath` / 头像候选键与基准域；
- `todo`：`listPath`、`keyFields`、`remoteKeyTemplate`、`localIdTemplate`（必须以 `<id>-`
  开头）、字段路径、`endTime`（ISO 或 PATTERN + 固定时区，缺省 Asia/Shanghai）、
  过滤规则（requireStudent / skipLocked / skipOverdue）、备注与详情链接模板、`autoGroups`；
- `timetable`（可选）：`entryUrl`/`allowedHosts`/`userAgent`/介绍与默认课表名；
  `basePath` 或 `baseMarker`；`semester`（页面 selector/global）；`requests`
  （student/schedule/slots/week，路径同源、字段模板只允许 `{semesterCode}` /
  `{semesterLabel}` / `{studentId}`）；`slots`（或 `fixedSlots`）与 `courses` 的字段路径；
  `weeksFormat=BITMAP`（第 i 位 = 第 i+1 周）；`term`（CURRENT_WEEK 或 DATE）。
  完整字段表见 `tools/schoolsync/README.md` §4.6。

声明式 codec 与编译期 codec 遵守**同一组不变量**：跳过顺序（非学生 → id 非法 → 标题空 →
无截止 → 截止解析失败 → 锁定 → 过期）、固定哈希配方
`sha256(标题|截止原文|课程名|类型)`、组键 `<id>:<group>`、本地 id 前缀 `<id>-`。
`RemoteSyncInvariantContractTest` 用 demo 声明跑完整契约套件（基类零改动）。

### 10.4 接入流程（发布者）

1. 复制 `tools/schoolsync/templates/demo.json` → `schools/<id>.json`，填写真实协议；
2. 在 `tools/schoolsync/index.json` 登记 `{ "id": "<id>", "file": "schools/<id>.json" }`；
3. push 到 Gitee 远端仓库 `gitee.com/ChengFY0710/classpp_schoolsync`（main 分支）；
4. 用户在学校选择浮层手动点击「更新远端学校列表」，成功后即可在选择器看到新学校；
   声明保存到本地，重启后仍可用（不会自动联网更新）。

**纪律**：demo 模板只作复制起点，**不进入 index**；单校声明坏只跳过该学校，不拖垮整批；
不要修改已发布学校的 `id`（会丢失已导入待办的归属）；破坏性 schema 变更提升
`schemaVersion`（旧客户端整体跳过而不是误读）。
