# 学校适配指南（多学校「账号与同步」）

> 适用对象：为本仓库接入一所新的学校（待办同步 / 网页登录 / 原生登录 / 教务课表导入）。
> 通用工具包位于 `data/sync/`，厦大（`data/xmu/` + `schools/xmu/`）是参考实现。
>
> **纪律**（继承《实施指导-多学校账号同步适配》§五 / `docs/AGENTS.md`）：
> - 本仓库禁止模拟器/真机验证；验收 = 编译 + 单测 + 静态守卫 + 评审清单；
> - 真实学校账号联调由适配开发者自行完成（Phase 5），不要把真机步骤写进本仓库测试；
> - `data/xmu/` 是冻结层：不要为了接新校修改它；通用层不得 import `data.xmu`；
> - 任何存储位置改动必须与 `backup_rules.xml` / `data_extraction_rules.xml` 同提交。

## 0. 一页总览

```
schools/<id>/                 # 一校一文件夹，自包含
├─ <Id>SchoolProvider.kt      # SchoolProvider：声明 spec + 装配 session
├─ <Id>SyncCodec.kt           # SyncCodec：远端协议 → Todo
├─ <Id>SessionApi.kt          # 可选：原生取数（实现 SessionApi）
└─ <Id>LoginClient.kt         # 可选：原生登录（实现 LoginClient）

data/sync/                    # 通用层（学校无关，不要往里写学校逻辑）
├─ SchoolSpec / SchoolSession / SchoolRegistry / SyncTypes
├─ engine/   SyncCodec、SchoolSyncEngine、SchoolSyncStore
├─ credential/ SchoolSecureStore、KeystoreCipher、AutoRenewManager、AutoRenewSessionRouter
├─ webview/  WebViewPolicy、WebSessionDriver、WebFetcher
├─ net/      HttpTransport、OkHttpTransport、CookieMirror、SessionCookieHolder
└─ media/    AvatarCache、HttpAvatarFetcher

ui/schools/                   # 通用 UI 绑定
├─ SchoolUiBindings.of(session) → 已注册自定义 UI 或 GenericSchoolUi
└─ GenericSchoolUi            # 纯声明学校的零代码 WebView 登录浮层
```

能力槽位与声明必须一致（注册表装配后硬校验）：

| 能力 | 会话槽位 | UI 表现 |
| --- | --- | --- |
| `NATIVE_LOGIN` | `autoRenew: AutoRenewService` | 凭据浮层 + 自动续期开关 |
| `WEBVIEW_LOGIN` | `webViewLogin: WebViewLoginSpec` | 网页登录入口（含备用登录方式） |
| `SCHEDULE_IMPORT` | `scheduleImport: ScheduleImportService` + `timetableIntro` | 教务导入入口/介绍卡 |

至少声明一种登录能力；`timetableIntro` 必须与 `SCHEDULE_IMPORT` 成对出现。

## 2. 选登录方式

### 2.1 只做 WebView（推荐给不想接触密码的学校）

填 `WebViewLoginSpec`，**不写任何 UI 代码**：`GenericSchoolUi` 会自动接手登录浮层，
`WebFetcher` 负责已连接后的无头取数。

```kotlin
internal val ABC_WEB_VIEW = WebViewLoginSpec(
    entryUrl = "https://lms.abc.edu.cn/user/index?version=v1",
    allowedHosts = setOf("lms.abc.edu.cn", "ids.abc.edu.cn"),
    dataHost = "lms.abc.edu.cn",
    profilePath = "/api/profile",
    todosPath = "/api/todos",
    userAgent = DESKTOP_UA,   // null = 系统默认
)
```

校验规则（注册表装配时硬校验，`WebViewPolicy.validate`）：
- 入口 URL 必须 https、默认 443、无 userinfo、host ∈ `allowedHosts`；
- `allowedHosts` 只允许小写域名（至少一个点），禁 IP 字面量 / 通配符 / 显式非 443 端口；
- `dataHost ∈ allowedHosts`；不同学校的白名单**不得重叠**（共用 CAS 域会让 cookie 互串）；
- `profilePath` / `todosPath` 必须是 `/` 开头的安全路径（禁引号/反斜杠/空白，防 JS 注入）；
- 加固项（禁 file/content、禁混合内容、SSL 拒错、白名单导航）锁死在 `WebViewPolicy`，
  spec 无法关闭。

登录态确认口径（profile 正文有效性）：默认「JSON 对象」；建议在会话上注入更严格的
校验（如必须含非空 uid），避免 200 的登录页 JSON 被误判为已登录：

```kotlin
override val webViewProfileValidator: ((String) -> Boolean)? = { raw ->
    runCatching { ScheduleJson.decodeStorage<AbcProfileDto>(raw).id > 0 }.getOrDefault(false)
}
```

### 2.2 原生登录 + 自动续期（可选）

实现两件事：

1. `LoginClient`：账号密码 → 会话凭据（用 `HttpTransport` 发请求，密码只提交给学校声明的身份主机）；
2. `SessionApi`：会话 → `LoginRaw(profileRaw, todosRaw)`（解析交给 codec）。

```kotlin
internal class AbcLoginClient(
    private val transport: HttpTransport,
) : LoginClient {
    override suspend fun login(username: String, password: String): LoginResult {
        // …CAS/Keycloak 链路…
        return try {
            LoginResult.Ok(LoginSession(cookieHeader = "sid=$sid", cookies = mapOf("sid" to sid)))
        } catch (e: SocketTimeoutException) {
            LoginResult.Timeout
        } catch (e: IOException) {
            LoginResult.NetworkError
        }
    }
}

internal class AbcSessionApi(
    private val transport: HttpTransport,
    private val cookies: SessionCookieHolder,
) : SessionApi {
    override suspend fun fetchSession(): FetchOutcome {
        // 带 cookies.header 请求 profile/todos；按状态码分类：
        // 302→登录页 / 401 / 403 = SessionExpired；5xx = ServiceBusy；IO = NetworkError；
        // 200 但结构不符 = FormatChanged
    }
}
```

装配 `AutoRenewManager`（单飞 / 失败即停 / 60 秒退避全部已封装）：

```kotlin
val autoRenew = AutoRenewManager(
    store = SchoolSecureStore(appContext, "abc"),   // sync_secure.xml，按校分键
    loginClient = AbcLoginClient(OkHttpTransport(userAgent = DESKTOP_UA)),
    sessionApi = abcApi,
    cookieHolder = SessionCookieHolder(),
    cookieMirror = AndroidCookieMirror,             // 关闭自动续期后网页仍可复用会话
    mirrorHost = ABC_WEB_VIEW.dataHost,
    logger = SyncDebugLog::d,
).also { it.bootstrap() }
```

路由（原生优先、WebView 兜底）直接复用：

```kotlin
val api: SessionApi = AutoRenewSessionRouter(autoRenew, WebFetcher(appContext, ABC_WEB_VIEW, validator))
```

> 不想保存密码就不要声明 `NATIVE_LOGIN`：UI 会自动隐藏自动续期相关行。

## 3. 实现 `SyncCodec`（同步的核心）

```kotlin
internal class AbcCodec(private val clock: () -> Long) : SyncCodec<AbcRemoteTodo> {

    override val source: String = "abc"      // 必须等于 spec.id

    // 确定性本地 id：重复同步天然幂等；必须以 "<id>-" 开头
    override fun localId(remoteKey: String): String =
        remoteKey.removePrefix("abc:").split(':').let { (courseId, id) -> "abc-$courseId-$id" }

    override fun matchesLocalId(id: String): Boolean = id.startsWith("abc-")

    override fun parseProfile(raw: String): RemoteProfile?  // uid / accountName / avatarUrl
    override fun parseTodos(raw: String): List<AbcRemoteTodo>?  // 结构不符返回 null

    override fun remoteKey(remote: AbcRemoteTodo): String = "abc:${remote.courseId}:${remote.id}"
    override fun remoteHash(remote: AbcRemoteTodo): String  // 只落哈希，不存标题原文
    override fun toTodo(remote: AbcRemoteTodo, fetchedAt: Long): Todo?  // null = 跳过
    override fun skipReason(remote: AbcRemoteTodo): SkipReason?         // 锁定/过期/非法…
    override fun autoGroupKey(remote: AbcRemoteTodo): String? =
        if (remote.type == "homework") "abc:homework" else null
    override fun isOwned(todo: Todo): Boolean =
        todo.source == source || matchesLocalId(todo.id)
}
```

要点：
- **远端唯一键** = 校内唯一（如 `courseId + activityId`）；entries 映射与去重都按它配对；
- `remoteHash` / `localHash` 只存哈希；不要往状态文件写标题/课程名原文；
- `skipReason` 与 `toTodo` 的契约：`skipReason == null` 时 `toTodo` 应非 null；
  接口形态变化导致的「非空但解析失败」请用 `SkipReason.DeadlineUnparseable` 单独计数；
- 过期判定需要「现在」时，由构造注入时钟（引擎只把 `fetchedAt` 传给 `toTodo`）。

## 9. 常见问题

**Q：`schools/<id>` 可以 import `data/xmu` 吗？**
只有厦大适配层可以（冻结协议是它的实现）。新校不得依赖 `data/xmu`，否则架构守卫会失败；
加密/原子写/WebView 加固等通用能力都已在 `data/sync` 提供等价实现。

**Q：能不做 WebView、只做原生登录吗？**
可以。声明 `NATIVE_LOGIN`、`webViewLogin = null`，UI 不显示网页登录入口。但自动续期失败
（验证码/改版）后没有兜底路径，用户只能重输密码——产品上需接受这一点。

**Q：教务课表导入必须实现吗？**
不必。不声明 `SCHEDULE_IMPORT` / 不提供 `scheduleImport` 时，`ScheduleScreen` 自动隐藏入口。

**Q：头像必须提供吗？**
可选。不传 `AvatarCache` 或不提供 `avatarUrl` 时 `avatarImage` 恒为 null，UI 走姓名首字占位。

**Q：每日自动同步会自动支持新校吗？**
会。`DailySyncRunner` 只作用于活跃学校，开关读 `session.dailySync`（`sync_prefs` 按校分键），
切校后闹钟自动重排。非活跃学校不参与（选择浮层会提示）。
