## 0. 一句话总览

Classpp 是一个**单模块、100% Kotlin、100% Jetpack Compose** 的安卓课表应用：不依赖 DI 框架、ViewModel、Navigation-Compose、Room、Retrofit、WorkManager，用自研的依赖容器、浮层导航、文件存储与 OkHttp 传输层承担全部职责；视觉层自建设计 token 体系，并引入 Haze 毛玻璃、Kyant0 连续曲率形状 / 液态玻璃、Glance 小组件。

| 维度 | 选型 |
|---|---|
| 语言 | Kotlin（无 Java 源文件） |
| UI | Jetpack Compose + Material 3，单 Activity |
| 架构 | 单 Activity + 手写依赖容器 + Repository + 文件 Store + `StateFlow` |
| 持久化 | 单 JSON 文件（`kotlinx.serialization`）+ SharedPreferences（密文走 Keystore） |
| 并发 | Kotlin Coroutines / Flow（无 RxJava、无 LiveData） |
| 网络 | OkHttp 5（原生链路、AI SSE）+ 无头 WebView（会话型站点） |
| 构建 | Gradle 9.6.0 + AGP 9.4.1 + Version Catalog |
| 测试 | JUnit 4 + Fake 注入 + 契约测试（不跑模拟器/真机） |
| 规模 | `main` 339 个 `.kt`、95,603 行；测试 165 个文件、1,633 个 `@Test` |

## 2. 语言与并发

- **全 Kotlin**：`app/src/main` 下 339 个 `.kt`，无 `.java` 源文件。
- **协程为唯一异步范式**：118 个文件引用 `kotlinx.coroutines`，33 处 `StateFlow`。
- **无 RxJava、无 LiveData、无 `CompletableFuture` 业务代码**；阻塞 I/O 一律包 `Dispatchers.IO`，WebView 驱动固定在 `Dispatchers.Main`。
- **无 `ViewModel`**：页面状态由 Repository 持有的 `StateFlow` + Composable 内 `remember`/`rememberSaveable` 承担，随 Activity 生命周期存在。
- **取消语义显式建模**：WebView、AI SSE 等长任务都定义了「取消必须解除阻塞读」的接口契约，并配 Fake 实现做 JVM 单测（见 `AiClient` 的 `AiStreamResponse` 契约）。

## 4. 应用架构

### 4.1 分层

```
MainActivity（单 Activity，edge-to-edge）
  └─ ui/                      Composable 页面与组件
       ├─ theme/              设计 token（颜色/间距/形状/字号/字体）
       ├─ motion/             动效原语
       ├─ navigation/         TabPager + 底栏
       ├─ components/         跨页组件（卡片/浮层/选择器/图表…）
       ├─ ai/ note/ day/ schedule/ settings/ schools/   业务页面
       └─ widget 桥接
  └─ data/
       ├─ AppContainer.kt     进程级依赖容器（唯一装配点）
       ├─ *Repository.kt      领域仓库（内存态 + StateFlow + 校验 + 持久化编排）
       ├─ store/              文件存储（Schedule / Todo / Tag / Attachment）
       ├─ model/              纯数据模型 + kotlinx.serialization
       ├─ ai/                 AI 会话、协议编解码、工具调用
       ├─ sync/               学校无关同步通用层
       │    ├─ engine/        通用同步引擎（单飞/预览-确认/只增不改）
       │    ├─ credential/    Keystore 加密、原生登录、自动续期
       │    ├─ net/           HttpTransport、Cookie 镜像
       │    ├─ webview/       无头 WebView 会话驱动
       │    └─ remote/        远端声明学校（JSON 目录）
       ├─ xmu/                厦大冻结层（原生登录/教务/待办 API）
       ├─ wakeup/             Wakeup 口令导入
       ├─ backup/ export/     备份归档与分享码
       ├─ update/             应用内更新
       ├─ notification/ alarm/ 通知与精确闹钟
       └─ calendar/           系统日历写入
  └─ schools/<id>/           一校一包：SchoolProvider + SyncCodec（+ 可选 SessionApi/LoginClient）
```

### 4.2 关键设计决策

1. **依赖注入**：`data/AppContainer.kt` 手写单例容器，首次调用完成磁盘装载，之后进程内恒定同一实例；测试不走容器，各仓库 `create(...)` 注入 fake store。
2. **导航**：没有 `NavHost`。顶层是 `TabPager`（横向分页）+ 底部玻璃胶囊 `BottomNavBar`；页内层级是 Compose 浮层（`OverlaySheet`）与整屏对话框（`FadeOverlayDialog`），层级与退场动效由 `ui/motion` 统一编排。
3. **状态**：Repository 暴露 `StateFlow`；写入失败回滚内存态（`StoreResult` → 仓库回滚）。UI 读状态用 `collectAsState`，不引入 ViewModel 层。
4. **学校适配**：通用层 `data/sync/` 不 import `data.xmu`（架构守卫测试约束）；`schools/<id>/` 自包含。能力槽位（`NATIVE_LOGIN` / `WEBVIEW_LOGIN` / `SCHEDULE_IMPORT` / `TODO_NOTE_SYNC`）声明后由注册表硬校验，UI 只按能力显隐、不认学校 id。
5. **远端学校**：`data/sync/remote/` 从 Gitee 拉取 `index.json` + `school-<id>.json` 声明，零代码接入；冷启动只读本地缓存，手动更新才联网。
6. **同步不变量**：通用引擎强制「单飞、预览-确认、只增不改、账号一致性、跨校隔离、原子写、失败分类不兜底」等 11 条，由契约测试约束（`docs/学校适配指南.md`）。

## 5. 数据持久化

### 5.1 存储介质

| 数据 | 位置 / 实现 | 格式 |
|---|---|---|
| 课表 | `filesDir` 下 `FileScheduleStore` | 单 JSON，`formatVersion = 2` |
| 待办 | `FileTodoStore` | 单 JSON，`formatVersion = 1` |
| 标签 | `FileTagStore` | 单 JSON，`formatVersion = 1` |
| 待办附件 | `TodoAttachmentStore`：`todo_attachments/<attachmentId>/<fileName>` | 原文件复制，`.part` 临时文件后改名 |
| AI 会话 | `FileAiChatStore` + `AiImageStore` | JSON + 图片文件 |
| 学校同步映射 | `SchoolSyncStore` | JSON（只存映射/哈希/状态，不存标题原文） |
| 设置/开关 | `SharedPreferences`（`Prefs*` 系列） | 键值 |
| 敏感凭据（学校密码、AI Key） | **Android Keystore AES-256/GCM** → 密文 Base64 存 SharedPreferences | 信封 `[version][ivLen][iv][ciphertext]` |
| 远端学校声明缓存 | `filesDir/sync_remote/` | JSON |
| 备份导出 | 用户选择的 SAF 目标 | 未加密 ZIP |

### 5.2 文件写协议（三个 Store 共用）

```
写：tmp（写入 + fsync） → bak（备份本次将提交的数据） → rename 覆盖主文件
读：主文件 → 解析失败读 bak → 双坏改名 <name>.corrupt-<millis>.json 留证并返回空库
版本：formatVersion 高于当前版本按损坏处理
```

- 协议 KDoc 在 `data/store/ScheduleStore.kt`，`TodoStore` / `TagStore` 逐字复用。
- 所有 Store 是阻塞 I/O 接口，由仓库包 `Dispatchers.IO`；JVM 单测直接用临时目录验证。
- **存储位置改动必须与 `res/xml/backup_rules.xml` / `data_extraction_rules.xml` 同提交**（`docs/学校适配指南.md` 纪律）。
- 含 Keystore 密文的文件（如 SharedPreferences `ai_secure`）被备份规则排除——密钥不随备份迁移，密文到新机解不开，属有意设计。

### 5.3 无数据库、无 DataStore 直接依赖

- 未使用 Room / SQLDelight / SQLite。
- 唯一出现 `androidx.datastore` 的地方是 Glance 小组件（由 Glance 传递依赖提供 `stringPreferencesKey`），业务层不直接用 DataStore。

## 6. 网络与外部集成

| 场景 | 实现 | 端点 |
|---|---|---|
| 厦大原生登录 / 待办 / 教务 | `data/xmu/` + OkHttp（**IPv4-first DNS**、`callTimeout` 兜底） | `lnt` / `c-identity` / `ids` 系列（`*.xmu.edu.cn`） |
| 网页登录 / 教务网页导入 / Wakeup 抓取 | 无头 WebView（不入视图树，主线程驱动 + 总超时看门狗 + `CookieManager` 会话复用 + `evaluateJavascript` 轮询取回） | 学校声明的 https 白名单域 |
| 附件下载 | `HttpRemoteAttachmentFetcher`（OkHttp） | 学校声明域 |
| AI 对话 | OkHttp + **SSE 流式**，支持 **OpenAI 兼容** 与 **Anthropic** 两种协议 | DeepSeek / 智谱 GLM / 通义千问 / Kimi / MiMo 预设 + 自定义 |
| 远端学校目录 | `OkHttpTransport` 拉取 `index.json` | `https://gitee.com/ChengFY0710/classpp_schoolsync/raw/main/` |
| 应用内更新清单 | 同一仓库 `update.json`（`schemaVersion` + 版本 + APK 直链/校验 + 发布页 + 分语言说明） | 同上 |
| Wakeup 适配脚本 | 下载 `wake_up.js` 后交给无头 WebView 执行 | `https://gitee.com/XingHeYuZhuan-gh/shiguang_warehouse/raw/main/resources/GLOBAL_TOOLS/wake_up.js` |

### 6.1 OkHttp 的两个非常规用法

1. **IPv4-first DNS**：厦大三台主机同时发布 A + AAAA 记录，校园网外与模拟器 IPv6 路由常不可达；`HttpURLConnection` 无 happy-eyeballs 会长时间黑洞。项目实现了「域内存在 A 记录就只走 IPv4」的解析器，并用 OkHttp `callTimeout` 兜底整次调用。
2. **AI 流不设整次调用上限**：LLM 长回答可持续数分钟，关闭 `callTimeout`；连接超时 10s，取消经 `call.cancel()` 断 socket 解除阻塞读。

### 6.2 AI 能力边界

- **BYOK**：API Key 只进请求头，不落日志、不进明文备份，存 Keystore 加密的 SharedPreferences。
- **工具调用闭环**：`AiToolRegistry` / `AiToolExecutor` / `AiReadTools` / `AiWriteTools`，模型可读写课表与待办；写入走统一的待办变更校验与草稿映射。
- **课表识别**：支持图片/文本经 AI 解析为课表导入（`AiScheduleRecognition` + `AiScheduleImportCodec`）。
- **调试**：`AiDebugTrace` 记录协议往返（不含 Key），供设置页诊断。

## 10. 刻意不引入的技术（决策记录）

| 技术 | 替代方案 | 理由 |
|---|---|---|
| Hilt / Dagger | `data/AppContainer.kt` 手写容器 | 依赖图小且稳定，测试靠构造器注入 fake，不引入注解处理器与编译期成本 |
| AndroidX ViewModel | Repository `StateFlow` + Compose `remember` | 单 Activity、页面状态本就随进程存在；少一层生命周期桥接 |
| Navigation-Compose | `TabPager` + `OverlaySheet` 浮层体系 | 需要页面不销毁的横向分页与页内浮层层级动效，NavHost 的返回栈模型不匹配 |
| Room / SQLDelight | 单 JSON 文件 + 原子写协议 | 数据量小（课表/待办/标签），整库读写 + 备份/导出天然一致；无迁移框架负担 |
| DataStore（业务层） | SharedPreferences + 文件 Store | 见上；DataStore 仅经 Glance 传递出现 |
| Retrofit / Moshi / Gson | OkHttp + `kotlinx.serialization` 手写编解码 | 接口形态异构（SSE、表单、学校私有协议），统一编解码器比 Retrofit 注解更直接 |
| WorkManager | `AlarmManager` + 静态 Receiver | 需要精确到分钟的提醒与开机自愈，WorkManager 的时间精度与最小间隔不满足 |
| 崩溃监控 / 分析 SDK | `SyncDebugLog` / `AiDebugTrace` + `runCatching` | 隐私优先：不采集设备标识、不上报用户数据 |
| Accompanist / 第三方动画库 | 自研 `ui/motion/` | 需要与设计稿逐帧对齐的手势、过冲、浮层编排 |
| 图标字体 / 图标库 | 自绘 vector drawable | 减少依赖与包体，图标风格统一 |
| Baseline Profile | 未启用（`baselineprofile/` 为残留） | 当前无启动性能专项；目录与 `:app` 无构建关联 |

## 11. 已知技术债与风险

1. **巨型 Composable 文件**：`ui/note/TodoScreen.kt`（约 171 KB）、`ui/day/DayScreen.kt`（约 146 KB）、`ui/schedule/ScheduleScreen.kt`（约 142 KB）、`MainActivity.kt`（约 66 KB），单文件职责过宽，重构与增量编译成本高。
2. **Haze 2 的 RenderNode 递归崩溃**：调休浮层、账号与同步设置子页曾触发无限递归，当前以「源侧退让 / 结构重写延后」规避（`HazeRetreat`、`rememberPopupActionGate`），属未根治的库级问题，升级 Haze 时必须回归。
3. **`baselineprofile/` 残留**：目录只剩构建产物、未 `include`，易误导新贡献者。
4. **无崩溃上报**：线上问题只能靠用户反馈与调试日志，排障成本高（隐私换取的取舍）。
5. **未加密备份 ZIP**：导出文件可被任意解包，README 已明示；依赖用户自行保管。
6. **IPv4-first DNS 是学校域特例**：规则只对厦大域生效，新校若同样双栈不可达需在适配层声明。
7. **版本激进**：AGP 9.4.1 已超出官方兼容窗（官方上限 9.3.1）一个小版本；Kotlin 2.4.21 与 Compose BOM 2026.09.00 的元数据对齐靠人工核对，升级窗口窄。
8. **`versionName` 仍为 `0.1.7-alpha`**：API/数据格式仍可能随版本调整，`formatVersion` 升级必须写迁移或降级策略。

## 12. 升级与改动的硬约束

1. **Kotlin 三件套必须同版本**：KGP、`org.jetbrains.kotlin.plugin.compose`、`org.jetbrains.kotlin.plugin.serialization` 共用 `kotlin` ref；任一单独升级都会导致 Compose 编译器版本校验失败。
2. **声明必须对齐实际解析值**：`core-ktx`、`activity-compose`、`lifecycle` 都曾出现「声明值被传递依赖抬高」的失真，`libs.versions.toml` 的注释记录了每次对齐原因，改版本前先看注释。
3. **Haze 2.x**：`HazeBlurStyle` 按 identity 比较，Style 必须在组合期 `remember`；动态值以 `State` 传入、在 Style 块内读取，不得作为 `remember` key。
4. **Compose Multiplatform 编译的库**（Haze / Shapes / Backdrop / Markdown Renderer）要求项目 Kotlin 版本不低于其元数据版本；升级 Kotlin 需同步验证这四者。
5. **存储位置改动**：与 `backup_rules.xml` / `data_extraction_rules.xml` 同提交，并检查 Keystore 密文文件是否被正确排除。
6. **UI 改动**：间距/颜色/字号一律走 `ui/theme` token，受三份规范与静态守卫测试约束；不覆盖 `CardSection` 默认间距；Haze 采样一律 `HazeSourceSelection.Behind`。
7. **架构守卫**：`data/sync/` 不得 import `data.xmu`；`schools/<id>/` 自包含；跨层依赖新增前先看 `docs/学校适配指南.md`。
8. **验证口径**：禁止模拟器/真机验证，交付以编译 + 1,624 项 JVM 单测 + 静态守卫为准（9 项仪器测试不在日常验收链路内）。
